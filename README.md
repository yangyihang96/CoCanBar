# 小电拼菜单栏

简体中文 | [English](README.en.md)

[![CI](https://github.com/yangyihang96/CoCanBar/actions/workflows/ci.yml/badge.svg)](https://github.com/yangyihang96/CoCanBar/actions/workflows/ci.yml)

制糖工厂「小电拼」（CP02 / CoCan）的 Mac 菜单栏 app，非官方第三方工具：

- **读数**：局域网 `http://<设备>/metrics.json`，每隔几秒读一次，不需要登录。Mac 和小电拼不在同一个网络时，配好 MCP 的设备改读官方 MCP 的云端读数，每 15 秒一次，见「不在同一个网络时」。
- **控制**：官方 MCP（`mcp.thecandysign.com`）。MCP 地址含 token，只保存在钥匙串里。
- **识别**：每个口接的是什么设备、电量、PD 档位和线材，用官方 MCP 的只读工具读，见「设备识别」。
- **温度、电量、曲线**：每个口的芯片温度档位、本次已充的电量、最近 30 分钟到 2 小时的功率曲线（重开 app 后接着显示），见「芯片温度、本次电量和充电曲线」。
- **桌面小组件**：小、中、大三种尺寸，可以选显示哪一台，右上角能刷新；菜单栏 app 没开时小组件自己读局域网；大尺寸能直接开关端口，见「桌面小组件」。
- **快捷指令**：读取功率和状态、开关端口、切换充电策略、温控和屏幕亮度，见「快捷指令」。

「小电拼」「制糖工厂」等名称和商标归各自的所有者，本项目与制糖工厂没有关联。

## 上手

目前没有打包好的下载：给别人装的 app 要用 Developer ID 签名并经过公证，这里还没做。需要用 Xcode 自己构建，见「[构建](#构建)」。

1. **构建并打开**：运行 `./scripts/build-app.sh`，打开生成的 `build/小电拼.app`。系统询问“本地网络”权限时点「允许」。
2. **绑定小电拼**：在小程序「龙虾服务」里点复制，整段粘贴到设置窗口的「设备」页，步骤见「[首次配置](#首次配置)」。
   只靠扫描局域网添加的设备只能看读数，开关和调节都要 MCP 地址。
3. **日常操作**：
   - 看读数：菜单栏显示所有在线设备的总功率。点它打开面板，每台设备一张卡片；点某个口，看协议、电压、电流和接的是什么设备。
   - 开关端口：在面板上点这个口，用详情条里的开关；或者用设置「调节」页「端口」卡片里的开关。关正在供电的口会先确认。
   - 换充电策略、温控、屏幕亮度：点卡片右上角的「调节」菜单；或者在「调节」页的模式、温控、状态屏卡片里点。切换策略前会先确认。
   - 临时分配功率：「调节」页的「临时功率分配」→「调整分配」，每个口拖滑块，点「应用…」后再确认一次。应用时所有口会重新握手。
   - 看功率曲线和接入的设备：「调节」页下面的「充电曲线」「在充设备」。
   - 有多台设备时：面板里每台一张卡片，「调节」页右上角切换。
   - 打开设置窗口：面板右上角齿轮里的「设置…」，或者「调节」菜单里的「端口开关、功率分配和全部调节…」。
   - 桌面小组件和快捷指令：见「[桌面小组件](#桌面小组件)」「[快捷指令](#快捷指令)」。

## 界面

菜单栏面板和小组件的样式照小程序「电控」页：奶油色底、白色卡片、橙红品牌色。
设置窗口的排版和配色照 [KangCharge](https://github.com/LeiZiKang/KangCharge)（MIT）的主窗口：奶油底、白卡片、一个橙色强调色，代码是另写的。
都跟随系统深浅色；KangCharge 只有浅色，深色外观换成同一色调的暖深灰。

配色有两套，面板、设置窗口和桌面小组件一起换，选择记在 App Group 容器的 `theme.txt` 里：

- **暖色**（默认）：奶油底 `#F8F5EC`、橙红强调 `#FF4719`，端口色是橙系；
- **冷色**：冷灰底 `#F0F4F9`、蓝色强调 `#2F7BF6`，端口色是从浅青到深蓝的渐变。

切换：面板右上角齿轮里的「换成冷色调 / 换成暖色调」，或者设置「通用 → 外观」里的「冷色调」开关。
芯片温度的圆点、在线/离线这类状态色只跟着底色微调明暗，色相不变（温度必须是绿-黄-红，不能跟着强调色变蓝）。

- **菜单栏**：糖标加所有在线设备的总功率（界面上不带单位，读屏时补「瓦」）。图标宽度固定，读数变化时不会左右挪。
- **面板**：
  - 顶部显示在线台数和在充口数，有多台时显示合计功率。
  - 每台设备一张卡片。名称和在线状态在卡片上方；卡片里是总功率、「调节」按钮、充电图谱和详情条。
  - 充电图谱每个口一根胶囊柱，柱高按功率占该口上限的比例取平方根，颜色跟随当前模式（小程序的场景配色）：
    - 空闲：斜线底纹；
    - 已连接、未取电：描边；
    - 关闭：虚线框。
  - 面板每次打开时，柱子依次长出来。系统开了「减弱动态效果」时不播放动画。
  - 点一个口，详情条显示协议、电压、电流、功率、已充时长和本次电量（读不到电量时显示分配功率），
    以及芯片温度（温度计图标）和这个口的开关。
    认出设备时，标题换成设备名和电量；鼠标停在上面显示完整的识别信息、本次电量、芯片温度和分配功率。
  - 关闭正在供电的口、切换充电策略之前，都先在详情条里确认。
  - 卡片高度固定。读数变化、选中端口、出现确认条，都不会让面板上下跳。
- **「调节」菜单**（卡片右上角）：
  - 充电策略（带图标和说明）、温控、屏幕亮度（子菜单）；
  - 「端口开关、功率分配和全部调节…」打开设置窗口的「调节」页。
- **设置窗口**：
  - 调节：
    - 页首：设备名和连接状态；有多台时在右上角切换，旁边是刷新和通用设置；
    - 充电模式：策略按钮、充电状态和温控快捷切换；
    - 功率图：每个口一根线连到画出来的小电拼，标出各口功率、协议和总功率；离线时整张变灰；
    - 端口：每个口接的设备或状态、协议、电压、电流、功率、芯片温度和开关；
    - 设备信息、温控、状态屏（屏幕亮度；设备报告支持时还有 CP02S 的屏幕显示选项）、端口功率分配（临时）；
    - 充电曲线：一个口或各口合计的功率，最近 30 分钟或 2 小时；
    - 在充设备：每个口接的设备、电量和电池健康、PD 档位、线材、本次已充和芯片温度。
  - 设备：名称、PSN、主机、MCP 地址（存钥匙串），以及测试连接、扫描局域网、删除设备。
  - 通用：外观（暖色 / 冷色调切换）、刷新间隔、登录时启动。

## 能调的项目

官方 MCP 的写操作全部可以在 app 里调：

| 项目 | MCP 工具 | 在哪里调 |
| --- | --- | --- |
| 端口开关 | `turn_on_port` / `turn_off_port` | 面板详情条、「调节」页 |
| 充电策略：自由流、睡眠充、性能模式、极速单充 | `set_charging_strategy`（0 / 1 / 7 / 8） | 「调节」菜单、「调节」页 |
| 魔拟充（小家电模式） | `set_usba_charging_mode` | 「调节」菜单、「调节」页 |
| 温控：性能温控 / 安心温控 | `set_temperature_mode`（0 / 1） | 「调节」菜单、「调节」页 |
| 屏幕亮度：关 / 低 / 中 / 高 | `set_display_intensity` | 「调节」菜单、「调节」页 |
| 端口功率分配（临时） | `set_port_power_allocation` | 「调节」页 |
| 屏显模式、待机显示、整点报时（CP02S） | `set_status_display_mode` / `set_idle_display` / `set_hourly_chime` | 「调节」页，设备报告支持时才显示 |

- 策略名称照小程序「模式」页。
  - 自由流、睡眠充对应 `FLEXAI_FAST` / `FLEXAI_SLOW`。
  - 睡眠充 = 1 是按小程序源码里 SLEEP → FLEXAI_SLOW 的对应关系定的。
- 温控名称照小程序：功率优先叫「性能温控」（更高效能），温度优先叫「安心温控」（更少发热）。
- 小程序里的「苹果全家桶」「自定义」走静态分配表，MCP 不能设置，所以这里没有。
- 功率分配的规则：
  - 每个口填 15 W 到该口上限，或者 0（按策略）；
  - 合计不超过整机上限，上限从 `get_machine_facts` 读；
  - 按开源固件的实现，应用时所有口会重新握手；之后插拔设备或开关任一端口，设备会回到策略分配。

## 设备识别

设置窗口「调节」页的「在充设备」列出每个口接的设备；面板详情条选中端口时也会显示。

- 数据来自官方 MCP 的 `get_port_pd_status` 和 `get_port_details`，都是只读工具。
  - 局域网的 `metrics.json` 在固件 2.2.0 上没有 PD 信息，所以没配 MCP 的设备不显示识别结果。
- 型号：设备在 PD 握手里报厂商号（VID）和产品号（PID），由官方服务端给出型号。
  - 服务端没给型号时，按厂商号显示厂商，内置常见手机、电脑、游戏机和配件厂商的表。
  - 芯片厂商的厂商号不当作品牌显示。
  - 少数设备（Apple、三星、任天堂）只在电池信息里报厂商号，这时用电池的厂商号补上，规则照小程序。
- 电量和电池健康：照小程序的换算和过滤规则。
  - 设计容量或满充容量不在 5–200 Wh 之间、健康度低于 75% 时，都不显示。
- PD：协议版本、设备当前请求的电压和电流、设备声明的最大功率、是否支持 PPS / EPR。
- 线材：
  - 带 E-Marker 的线显示最大电流和电压、USB 速率、是否有源线、是否支持 EPR；
  - 服务端认得的线显示品牌和型号；
  - 没有 E-Marker 的 C-C 线，按 PD 规范最高 3A。
- 什么时候读：
  - 插拔或重新握手后读一次（离上次至少 5 秒），20 秒后再补读一次，设备通常要到这时才把信息报全；
  - 之后每分钟读一次，更新电量；
  - 面板和设置页都关着时不读，没接设备时不问云端。
- 不走 PD 的设备（USB 普通充电、QC 等）认不出型号，只显示协议。

## 芯片温度、本次电量和充电曲线

都要配好 MCP 地址；用到的 MCP 工具都是只读的。

- 芯片温度：`get_port_details` 的 `die_temperature`。官方 MCP 只给档位，不给度数。
  - 显示为凉爽、温和、偏热、过热，配绿、黄、橙、红。
  - 实测见过温和和偏热，凉爽出现在 PD 状态里；过热（`hot`）是按命名推断的，还没见过。
  - 在「调节」页的「端口」卡片、「在充设备」和面板详情条显示；端口空着时不显示。
- 本次电量：这次插入以来充进去的电量。
  - 以 `get_port_details` 的 `session_charge_mwh` 为准，随设备识别一起读。
  - 两次读取之间，用局域网 `session_charge` 的增量往后推算，数字跟着读数每几秒更新。
  - `session_charge` 不是 mWh。在 CP02 Pro（固件 2.2.0）上，四个会话的比值是每 mWh 146,617–148,553；
    拿 5.4 W 的稳定负载按功率积分核对，差约 5%。比值每次用 MCP 读数现场校准，校准不了才用实测值 146,600。
  - 拔掉重插后会话号变了，旧读数不再显示。
- 充电曲线（设置窗口「调节」页）：
  - 一个口或各口合计的功率，最近 30 分钟或 2 小时，每 10 秒一个点。打开时默认看功率最大的在充口。
  - 最近 30 分钟从小电拼内存读取（`get_port_stats`）：固件每 10 秒存一个平均值，最多 180 个，断电清空。
    打开曲线时读一次，5 分钟内不重读；点刷新按钮重读。
  - 更早的部分是本 app 运行时用局域网读数记的，最多 2 小时。
    - 每分钟存一次盘，退出时也存（包括 `kill` 发的 SIGTERM），重开 app 后接着显示；读回时去掉超过 2 小时的点和已删除设备的记录。
    - 重读小电拼内存时，上一次读到的设备数据里比新一段早的部分并进本 app 的记录，不会丢。
  - app 没运行、设备离线的时段断开，不连成斜线。app 没开的时段如果还在最近 30 分钟内，下次重读小电拼内存时会补回来。
  - 鼠标停在曲线上，显示那个时刻的功率；单个口还显示电压和电流。
  - 曲线下面是平均（只算有功率的时段）、峰值、电压范围和本次已充；看合计时，显示这段时间大约充了多少。
  - `get_port_stats` 的点没有时间戳，按“最后一个是最新的”往前排，时间可能差几秒。
    这个顺序是实测确认的：隔 46 秒读两次，序列正好左移 4 个点。

## 不在同一个网络时

Mac 不在家、或者小电拼换了网络时，局域网读不到。配好 MCP 的设备会改读云端：

- 局域网连续两次读不到，就改用 MCP 的只读工具 `get_port_details`，每 15 秒读一次；连续失败时拉长到 30、60 秒。局域网一读到就切回来。
- 卡片标题旁的胶囊写「云端」，状态后面标「云端读数」。小组件的读数时间后面标「云端」，快捷指令「读取小电拼状态」也会注明。
- 云端读得到：每个口接没接设备、输出电压和电流、输入电压、协议、芯片温度、本次电量和会话号。读不到：开关状态、充电时长、分配功率。
- 开关状态：
  - 接着设备并且有输出电压（3 V 以上）的口，确定是开着的，照常显示开关；关掉正在用的口照常先确认。
  - 别的口（空着，或者接着但没有输出）开没开读不到：柱子上显示「–」，选中后详情条显示「打开」「关闭」两个按钮，不显示开关。
    这次运行里在本机发过开关命令的话，详情条写上什么时候在本机打开或关闭过。
  - `get_charging_status` 的位掩码表示接着设备（不取电的也会置位），也不是开关状态，所以没用它。
- 桌面小组件在云端读数时开关变灰，底部提示到菜单栏面板里开关：小组件的开关是按快照画的，开关状态未知时点下去未必是想要的方向。
- 读取功率、读取状态这两个快捷指令和小组件的刷新按钮，局域网读不到时会马上读一次云端，不等 15 秒。
- 充电曲线照常记录：每 15 秒一个点，曲线还是连着的（两点隔 30 秒以上才断开）。
- 局域网和云端都读不到时，卡片显示「局域网和云端都读不到」和云端的出错原因。没配 MCP 的设备只能读局域网，不在同一个网络时显示离线。
- 在家里也能看离网时的样子：用启动参数 `--cloud-only` 打开，app 不读局域网、只用云端读数：

  ```bash
  open build/小电拼.app --args --cloud-only
  ```

## 桌面小组件

右键桌面空白处 →「编辑小组件」，搜索「小电拼」，拖到桌面或通知中心。右键小组件 →「编辑“小电拼”」可以选显示哪一台，不选时显示第一台。

- 小：设备名、读数时间、总功率、在充口数；底部五个口的状态条，在充是端口色，空闲是浅槽，关闭是斜线。
- 中：再加最近 30 分钟的合计功率走势，右边是每个口的设备名和功率。
- 大：每个口的设备、电量、功率、电压、协议、本次电量、芯片温度和开关，底部是各口本次共充或提示。
  - 关闭正在用的口要点两次：第一次开关变成红色的「关闭？」，10 秒内再点才发送。
  - 没配 MCP 的设备不显示开关；菜单栏 app 没在运行、离线、读数过时、读数来自云端、正在执行别的操作时，开关变灰。
- 三种尺寸右上角都有刷新按钮。
- 配色和面板一样，端口颜色跟随本 app 上次设置的充电策略。
- 菜单栏 app 在运行时：
  - 小组件显示 app 写的快照。app 读到局域网数据后最多每 10 秒写一次；开关、插拔、在线状态、提示变了马上写。
  - 刷新次数由系统控制。开关、插拔这类变化，app 请系统刷新，最快 30 秒一次；只是功率变了，5 分钟最多一次；一直没有明显变化时也隔 14 分钟刷一次，免得读数被标成过时。在小组件上点了开关，执行完马上刷新。
    快照断档超过 1 分钟（比如 Mac 睡过一觉）后写的第一份也马上刷新：这段时间里小组件可能已经当 app 没在运行、改成了自己读局域网。
  - 点刷新按钮：请 app 马上读一次局域网，等它写出新快照（最多 3 秒）后刷新。
- 菜单栏 app 没在运行时（1 分钟没写快照，或者已经退出），小组件每次刷新自己读一次局域网：
  - 只读设备首页和 `metrics.json`，不需要令牌，小组件也拿不到令牌。
  - 用 app 最后记下的主机名，解析不到或读不到时试 app 上次用的 IP；每次都用首页里的 PSN 核对，地址上是另一台设备时不显示。
  - 最多等 10 秒。读到了约 5 分钟后再读，读不到 15 分钟后再试，系统还可能往后推。点刷新按钮会马上再读。
  - 同一次充电（会话号没变）时，设备名留着，本次电量按局域网 `session_charge` 的增量接着算。电池电量和芯片温度只有 MCP 能读，不显示。
  - 读数时间后面标「直读」，大尺寸底部写明 app 没开；走势图只有小组件自己读到的点。
  - 按 Apple TN3179，扩展和它所在的 app 共用「本地网络」权限：app 被允许过，小组件就能读。
  - app 正常退出时（包括 `kill` 发的 SIGTERM）先在快照里记下已退出，再请系统刷新小组件，不用等 1 分钟。
- 读数都标了时间（24 小时制）。超过 15 分钟没更新时，时间变成橙红色的「停在 14:05」，大尺寸底部提示点右上角刷新。
- 开关怎么发出去：
  - 小组件拿不到 MCP 令牌。点开关时，它在共享目录里写一条命令（哪台设备、哪个口、开还是关），再发通知叫醒菜单栏 app。
  - app 检查命令后，用自己钥匙串里的 MCP 地址发送，结果显示在小组件底部。
  - app 只执行 15 秒内发出、设备已添加、配好 MCP、在线、读数来自局域网并且有这个口的命令。
  - app 没在运行时开关是灰的。万一 app 刚好意外退出、3 秒内没回复，小组件撤回命令并提示，之后 app 打开也不会再执行。
- 要用 `scripts/build-app.sh` 打包，并且本机有 Apple Development 证书：app 和小组件通过 App Group 共享数据。临时签名时小组件读不到数据。

## 快捷指令

在「快捷指令」app 里搜索「小电拼」。动作在菜单栏 app 里执行，app 没开时系统会先打开它。

| 动作 | 参数 | 结果 |
| --- | --- | --- |
| 读取小电拼功率 | 设备、端口（都可以不选） | 功率（瓦，数字）；不选端口时是各口合计 |
| 读取小电拼状态 | 设备 | 一段文字：各口开关、功率、电压、协议、认出的设备、电量、本次电量和芯片温度 |

| 切换小电拼充电策略 | 设备、策略、切换前确认 | 完成提示 |
| 设置小电拼温控 | 设备、性能温控或安心温控 | 完成提示 |
| 设置小电拼屏幕亮度 | 设备、关 / 低 / 中 / 高 | 完成提示 |

- 不选设备时用第一台。
- 读数走局域网；不在同一个网络时，配好 MCP 的设备改读云端（见「不在同一个网络时」）。控制走官方 MCP，不在同一个网络也能发，但要先在 app 里配好 MCP 地址。
- 两个确认默认打开，和面板一样先问一句。做成自动化时可以关掉。
- 读取功率、读取状态、开关端口、切换充电策略这四个，还登记成了 App Shortcuts（「用小电拼读取功率」等），不用自己建快捷指令就能找到。
- 和小组件一样，要用 `scripts/build-app.sh` 打包：动作的元数据只有 Xcode 的构建流程会生成。

## 构建

需要 Xcode（已在 Xcode 27 / Swift 6.4 / macOS 27.2 上验证）。

```bash
./scripts/build-app.sh
```

- 脚本用 `CoCanBar.xcodeproj` 构建 Release（Apple 芯片和 Intel 通用），签名后生成 `build/小电拼.app`。
  - 桌面小组件扩展和快捷指令的元数据（`Metadata.appintents`）只有 Xcode 的构建流程会生成，所以正式包不用 SwiftPM 打。
  - 工程的四个目标直接引用 `Sources/` 下对应的文件夹，新增源文件不用改工程。
- 用本机的 Apple Development 证书签名。签名身份固定，重新构建后钥匙串仍然信任这个 app。
  - 还没有证书时，在 Xcode 的「设置 › 账户」里登录 Apple ID，选中团队后点「管理证书…」，加一张 Apple Development 证书。免费的 Apple ID 也可以。
  - 有多张证书时，可以用环境变量 `CODESIGN_IDENTITY`（证书的 SHA-1 或名称）指定用哪张。
- App Group 按证书的 Team ID 拼成 `<Team ID>.com.local.CoCanBar`，写进 `build/xcode/entitlements/` 里的权限文件。
  - macOS 上这种写法不需要描述文件。
  - 小组件扩展是沙盒的（系统要求），另加出站网络权限（`com.apple.security.network.client`），用来在 app 没运行时读局域网；它的 Info.plist 也有 ATS 本地网络例外。菜单栏 app 不是沙盒的。
  - 没有证书时退回临时签名：app 能用，但小组件读不到数据。
- 脚本检查 app 和小组件的版本号是否一致。改版本时，`Support/Info.plist` 和 `Support/Widget-Info.plist` 要一起改。
- 打包后注销并删掉 Xcode 的中间产物，免得同一个 bundle id 登记两份，快捷指令和小组件找到没签名的那份。
- 只在本机用、不需要 Intel 那一半架构时，可以用 `./scripts/build-app-local.sh`：和 `build-app.sh` 一样，只是只编 arm64。
  有的机器上通用构建会撞上 Swift 宏插件的报错，这个脚本绕开它，产物功能一样，只是不含 x86_64。

开发、单元测试和离屏截图用 SwiftPM：

## 首次配置

1. 打开 `build/小电拼.app`。系统询问“本地网络”权限时，点「允许」，否则读不到局域网数据。
   - 也可以之后在「系统设置 › 隐私与安全性 › 本地网络」里打开。
   - 按 Apple 的说明（TN3179），桌面小组件沿用 app 的这个权限。
2. 拿到 MCP 地址：在微信小程序「制糖工厂 CANDYSIGN」里进入这台小电拼，点底部的「设置」，在「核心功能」里打开「龙虾服务」（AI 自主控制），点复制按钮。
   - 复制出来的是一整段给 AI 的安装提示，里面带着这台设备的 MCP 地址，形如 `https://mcp.thecandysign.com/<PSN>/<token>/sse`。不用自己挑出来，整段粘贴进 CoCanBar 就行。
   - 「接入模型」保持默认的 OpenClaw 就行，地址以 `/sse` 结尾；换成别的模型时，地址可能以 `/mcp` 结尾，同样能用。token 是同一个，CoCanBar 都换成 `/mcp` 连接。
   - 页面上显示的地址打了码，复制出来的才完整。token 相当于这台设备的控制密码，不要发给别人。
   - 设备的授权里没有这项功能时，点「龙虾服务」会跳到订阅页；分享来的体验用户看不到地址。
   - 设备主人点「重置 MCP 密钥」后旧地址立即失效，要重新复制，再在 CoCanBar 的设备卡片里替换。
   - 每台小电拼的地址不一样，有几台就复制几次。
3. 打开面板，点右上角齿轮里的「设置…」，选「设备」页，用下面任一方式添加设备：
   - 把复制的内容粘贴到「添加设备」的「MCP 地址」框，点「用 MCP 地址添加」。PSN 从地址里自动识别，地址存进钥匙串。
   - 或者点「扫描局域网」，添加发现的 `cp02-<PSN>`。这种方式只能读数；要控制，还得在这台设备的卡片里粘贴复制的内容，点「保存地址」。
4. 在设备卡片里点「测试连接」，显示「连接正常：服务提供 N 个工具」就绑好了。
   - 名称可以改成「书桌」「沙发」这样好认的，按回车或离开输入框时保存。
   - 主机一般不用填，默认是 `cp02-<PSN>.local`。
5. 想开机后就有读数，在「通用」页打开「登录时启动」。

<img src="docs/screenshots/settings-devices.png" width="560" alt="设置窗口「设备」页">

也可以用启动参数批量导入。程序会从文件里提取所有官方 MCP 地址（`/sse` 结尾的也认），存进钥匙串：

```bash
open build/小电拼.app --args --import <含 MCP 地址的文件> --rename <PSN>=沙发
```

## 数据与安全

- 设备列表（名称、PSN、主机）存在 `UserDefaults`（`com.local.CoCanBar`），不含密钥。
- MCP 地址存在登录钥匙串，类型是通用密码，服务名 `com.local.CoCanBar.mcp`，账户是 PSN。
- 只认 `https://mcp.thecandysign.com/<PSN>/<token>/mcp` 和 `…/sse` 形式的地址（`/sse` 换成 `/mcp`）。粘贴整段文字时也只取这个主机的地址，token 不会发到别的主机。
- MCP 请求不跟随重定向，3xx 按错误处理。
- 界面上只显示去掉 token 的形式。错误信息里不带地址，服务端返回的错误文字也先脱敏再显示。
- 局域网读数会核对设备身份：
  - 主机名每分钟重新解析一次。
  - IP 变化或满一分钟时，用设备首页里的 PSN 核对。
  - 地址上是另一台设备时，不显示它的读数，以免对着错的端口状态去开关。
- 局域网接口本身没有鉴权，同一网段的任何设备都能读。这是设备固件的行为，不是本 app 引入的。
- 云端读数只在局域网读不到时才读，用的是 MCP 的只读工具 `get_port_details`（设备识别本来就在用它），每 15 秒一次，走同一个钥匙串里的 MCP 地址。
- 桌面小组件用的数据在 App Group 共享目录 `~/Library/Group Containers/<Team ID>.com.local.CoCanBar/` 里：
  - `snapshot.json`：设备名、PSN、主机名和 app 上次用的局域网 IP、在线状态、读数是否来自云端、各口读数和会话号、本次电量的换算比值，不含 MCP 地址和令牌。
  - `lan/<PSN>.json`：app 没在运行时小组件自己读到的数据，每台一个文件。
  - `commands/`、`replies/`：小组件发的开关命令和 app 的回复，处理完就删。
  - `pending.json`、`notice.json`：小组件自己的待确认和提示。
- 小组件扩展是沙盒的，有出站网络权限，只用来在 app 没运行时读局域网的设备首页和 `metrics.json`（和 app 一样核对 PSN）。
  它不读钥匙串，共享目录里也没有令牌，所以发不了 MCP 请求。
- 充电曲线记录存在 `~/Library/Application Support/com.local.CoCanBar/history.json`：按 PSN 分组的每个口的时间、功率、电压、电流，最多 2 小时，不含 MCP 地址。
- 开关命令 15 秒后过期，app 逐条检查后才发送，只能开关已添加、配好 MCP、在线的设备上存在的口。
  能以你的身份写共享目录的程序也能放命令进去，影响范围同样只限这些端口的开关，拿不到令牌，也控制不了别的设备。

## 自检工具

不开界面，验证读数和 MCP：

```bash
swift build --product cocan-probe
.build/debug/cocan-probe lan cp02-<PSN>.local
.build/debug/cocan-probe lan-check <PSN>
.build/debug/cocan-probe scan
.build/debug/cocan-probe mcp <含 MCP 地址的文件> <PSN>
.build/debug/cocan-probe mcp <含 MCP 地址的文件> <PSN> --schema
.build/debug/cocan-probe mcp <含 MCP 地址的文件> <PSN> get_charging_status
.build/debug/cocan-probe mcp <含 MCP 地址的文件> <PSN> --identify
.build/debug/cocan-probe mcp <含 MCP 地址的文件> <PSN> --history C1
.build/debug/cocan-probe mcp <含 MCP 地址的文件> <PSN> --cloud
```

- `lan-check` 和小组件在 app 没运行时一样读一次：解析 `cp02-<PSN>.local`（也可以在 PSN 后面给主机名或 IP），用首页里的 PSN 核对，再读实时数据。输出合计功率、口数和用时，不带 PSN 和地址。
- `mcp` 不带工具名时列出工具；`--schema` 打印每个工具的说明和参数结构；给工具名时调用这个工具。
- `--identify` 按 app 的规则识别各口接的设备，逐口打印型号、厂商号、PD 档位、电量、线材、芯片温度和本次电量。
- `--history C1` 打印小电拼内存里这个口最近 30 分钟的点数、时间范围、平均和峰值，以及最后 6 个点。
- `--cloud` 和 app 局域网读不到时一样读一次云端读数，逐口打印开关（读不到时写「未知」）、连接、电压、电流、功率、协议、芯片温度和本次电量，格式和 `lan` 接近，方便对照。
- 默认只允许 `get_` 开头的只读工具；开关端口、改策略等写操作必须加 `--allow-write`。

## 调试（只在 Debug 构建里有）

用演示数据检查界面。除了最后的 `--live-window`，这些参数都不轮询、不读钥匙串、不发请求：

```bash
swift build
.build/debug/CoCanBar --snapshot <目录>
.build/debug/CoCanBar --demo 1 --demo-window
```

- `--snapshot <目录>`：离屏渲染每个场景的面板，各出浅色、深色两张 PNG，然后退出。
- `--theme warm|cool`：这次运行用哪套配色（不写盘，不影响记住的选择），可以和其他调试参数一起用。
- `--demo <场景号>`：用演示数据跑真实的面板。场景号：
  1. 正常；
  2. 选中与切换策略；
  3. 关口确认与执行中；
  4. 离线与提示；
  5. 连接中报错与只读；
  6. 没有设备；
  7. 云端读数（局域网读不到，一台改读云端、一台两边都读不到）。
- `--demo-window`：把面板放进一个普通窗口，贴着主屏菜单栏显示。新版 macOS 的菜单栏图标由系统进程托管，程序里点不开 MenuBarExtra 的面板，所以借普通窗口看真实渲染。
- `--demo-settings [devices|general]`：另开一个窗口显示设置页，默认是「调节」页。
  - `--demo-settings-device <名称>`：「调节」页显示这台设备，默认第一台；
  - `--demo-cp02s`：当作 CP02S，状态屏卡片多出屏显模式、待机显示和整点报时。
- `--demo-menu`：窗口出来后，自动弹出第一张卡片的「调节」菜单。
- `--demo-light`：用浅色外观，默认深色。
- `--demo-capture <目录>`：在第 4 秒和第 8 秒，把演示窗口的内容各导出一张 PNG。
- 充电曲线：
  - `--demo-span 2h`：一打开就看 2 小时；
  - `--demo-curve-port <C1|A|合计…>`：一打开就看这个口；
  - `--demo-hover <分钟>`：当作鼠标停在几分钟前的位置，检查读数气泡。
- `--live-window`：不用演示数据，用真实设备把面板放进普通窗口，可以和上面的 `--demo-settings` 等参数一起用。
  - 和正式运行一样轮询设备、读钥匙串、调 MCP。窗口里的开关和按钮是真的，点了会控制设备。
  - 要读钥匙串里的 MCP 地址，需要把调试版放进和正式版相同的 app 包，用同一张证书签名，否则会弹钥匙串授权。

## 已知限制

- MCP 没有读取当前充电策略的工具。面板上显示的是“上次由本 app 设置”的策略。
- 芯片温度只有档位，没有度数。
- 本次电量的局域网换算比值是实测的经验值，固件没有文档；MCP 读不到时不显示电量。
- 充电曲线最多 2 小时。app 没运行的时段只能从小电拼内存补最近 30 分钟，更早的没有记录。
- 小程序的「电量统计」（今日、单日峰值、累计）走制糖工厂自己的云接口，MCP 没有对应工具，这里没有。
- 控制依赖官方云；断网时只有局域网读数可用。
- 云端读数（不在同一个网络时）：
  - 没有开关状态：空着的口、接着但没取电的口开没开读不到，见「不在同一个网络时」。
  - 协议是英文名。实测见过 `Not Charging`、`USB Legacy Charging`、`PD Fixed 5V`；别的名字按和小程序同名来认，认不出时显示原文。
  - 每 15 秒一次，每次都经过官方云，比局域网慢。2026-10-16 在两台 CP02 Pro 上紧接着读局域网和云端对照过，电压、电流、协议、连接状态一致，只有功率随时间变化的差别。
  - 还没有在 Mac 真正离开家里网络的情况下用过：验证用的是 `cocan-probe --cloud` 和 app 的 `--cloud-only`。
- 端口关闭后 `metrics.json` 怎么上报（`active` / `state` 的取值）还没有实测确认。目前按固件源码把 `INACTIVE` 当作已关闭。
- CP02S 的屏幕显示选项没有在 CP02S 实机上测过。`get_display_config` 的字段名没有文档，目前按取值识别。
- 功率分配的行为按开源固件源码推断，没有实测。
- 设备识别：
  - 线材识别、PD 档位已在 CP02 Pro 实机上核对过。
  - 服务端给出设备型号这一项还没见到过：测试时接的设备在 PD 握手里都没报厂商号。
    型号字段名（`device_name_*`、`device_brand_*`）参照线材字段的命名和其他开源客户端推断。
  - 电量、电池健康依赖设备上报，很多设备不报或报得不准，按小程序的规则过滤后仍只能参考。
  - 识别要走官方云，断网时不显示。
- 桌面小组件：
  - 什么时候刷新由系统决定，每天的次数也有限，读数可能比面板晚几分钟。
  - 开关要靠菜单栏 app 发。app 没在运行时，小组件能自己读局域网，但开关是灰的，电池电量和芯片温度也不显示。
    可以在设置的「通用」页打开「登录时启动」。
  - app 没运行时小组件自己读局域网：同一个读取函数已在两台实机上用 `cocan-probe lan-check` 核对过，
    但还没有在真实的小组件扩展里跑过；扩展沿用 app 的本地网络权限，是按 Apple TN3179 的说明推断的。
  - 目前核对的是离屏截图，还没有在真实桌面上逐个尺寸核对过；点小组件能不能打开 app 也还没核对。
  - 小组件上的端口开关和刷新按钮还没有在实机上端到端测过。
- 快捷指令：动作已经编进 app，系统也已登记，但还没有在「快捷指令」app 里实际运行过。

## 目录

```
Sources/CoCanKit/        网络、协议、钥匙串、和小组件共享的数据（不依赖界面）
Sources/CoCanStyle/      配色和共用的界面小件（面板和小组件都用）
Sources/CoCanBar/        SwiftUI 菜单栏 app（面板、充电图谱、充电曲线、设置页、快捷指令、给小组件写数据）
Sources/CoCanBarWidget/  桌面小组件；SwiftPM 构建出来的是离屏截图工具
Sources/cocan-probe/     命令行自检
Tests/CoCanKitTests/     解析、校验、共享数据、小组件直读和曲线存盘的单元测试
Support/                 app 和小组件的 Info.plist（LSUIElement、本地网络权限说明、ATS 本地网络例外）、图标
CoCanBar.xcodeproj/      打包用的 Xcode 工程（小组件扩展和快捷指令元数据只能由它生成）
scripts/                 打包签名（build-app.sh）、生成图标（make-app-icon.swift）
docs/screenshots/        README 里的截图（演示数据）
.github/workflows/       CI：每次推送用 SwiftPM 构建并跑单元测试
```
